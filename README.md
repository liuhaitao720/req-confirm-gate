# req-confirm-gate — 需求确认单回填门禁 Skill

把「需求分析完成 → 直接开写」改造为「需求分析完成 → **产出带编号的需求确认单** → 用户逐条回填 → **门禁解除** → 才允许开发」。

任何含需求分析环节的开发任务通用：新功能、改造、重写/移植。与 a2a-coder v3.2+ 联动——门禁未解除，不得拆解、不得建分支、不得写实现代码。

## 解决什么问题

源自真实项目实战教训（需求分析后直接开写，最终靠多版本确认单逐条回填才把需求钉死）：

1. **隐含默认值裸奔**——分析时替用户做的每个默认选择（算法/阈值/命名）不显式确认，开发到一半被推翻即返工
2. **口头确认无法追踪**——会话里的答复随上下文滚动丢失，没有可回溯的版本化文档
3. **AI 自行其是**——没有强制门禁时，即使需求未确认，开发流程也会"顺手"推进

## 核心流程

```
Step 1  提取      需求分析完成 → 先建端到端处理流程 → 筛确认项（原子决策点）
                 → 多Agent多视角提取、主代理汇总输出 → 通道判定（双通道均落盘）
Step 2  确认      轻量（≤8 项且无持久化需求）：会话内逐条确认
                 正式：确认单文档 → 用户按编号回填 → 意图解析 → 新版本（状态继承+编号映射）
Step 3  解除      全部条目达终态（或外部挂起已登记）+ 流程总览已拍板
                 + 用户解除指令锚定版本号 → 门禁解除 → 落盘凭据（含用户原话）
```

## v1.2 关键设计（经三方多视角评审后修订）

- **确认项 = 原子决策点**：一个条目一个可独立推翻的决策，复合打包即拆——计数按决策点，堵死打包逃逸
- **12 类通用类型体系**（跨软硬件，每类双形态）：范围/选型/接口/数据/默认值/交互/失败路径/可靠性/安全合规/性能资源/生命周期/部署协作
- **完整状态机**：待确认→已确认/已合并/已移除/已修改+已确认，另有**已否决、外部挂起（不阻断解除，转收口销账）、已重开、拆分**——覆盖真实回填全形态
- **回填意图优先**：裸编号列表=确认（移除必须带动词）、批量语法（区间/整章/默认+例外）、「后轮覆盖前轮、最新版为准」
- **凭据防伪**：解除凭据 = 解除标记 + **用户原话逐字引用** + 版本号锚定——AI 无法预知用户原话，用户扫一眼即辨伪；双通道均落盘
- **用户编辑面优先**：用户交回的整份修改文件永远优先于本地 markdown；生效版 = 固定文件名 + 头部版本号，历史靠 git
- **豁免治理**：触发词表 + 原话登记 + 累计护栏（>3 次强制回填）+ 紧急场景事后补登记
- **膨胀治理**：>30 项强制 P0/P1 分级，末轮放行对 P0 核心项单独点名——防批量全勾的纸面合规

## 安装

**Claude Code**

```bash
# 用户级（所有项目生效）
cp -r req-confirm-gate ~/.claude/skills/

# 项目级（仅当前仓库生效）
cp -r req-confirm-gate <your-repo>/.claude/skills/
```

**ZCode / 其他兼容 agent**

```bash
cp -r req-confirm-gate ~/.agents/skills/     # 用户级
cp -r req-confirm-gate <repo>/.zcode/skills/ # 项目级
```

安装后新开会话生效；需求分析完成后自动触发，也可显式 `/req-confirm-gate`。

## 与 a2a-coder 联动

a2a-coder v3.2+ 在设计门（步骤 0）与拆解门（步骤 1）之间消费本门禁：

- **设计阶段多Agent提取**：a2a 主控 spawn ≥3 视角代理并行提取确认项、汇总输出确认单（协议见 SKILL.md 1.4 节）
- 凭据**双验**：头部已解除 **且** 含用户原话引用，缺一不放行
- 确认单是 OPEN_ASSUMPTIONS 的唯一权威载体；门禁是入口门禁，实现期歧义走 OPEN_ASSUMPTIONS 收口销账，不中断自动链启
- 版本握手：a2a 检查本 skill ≥v1.2，不足显式警告

未装 a2a-coder 不影响本 skill 独立使用。
